01 / WHAT IT DOES

Stop assembling a string stack out of six libraries.

Use the same fast, consistent API from typo-tolerant search to biological alignment. Batch paths prepare the query once, release the GIL, and keep the SIMD lanes busy.

01

SEARCH + MATCHING

Find the right text even when the text is wrong.

Score one query against a whole corpus for fuzzy search, spell correction, record linkage, deduplication, and entity resolution.

02

SEQUENCE ALIGNMENT

Local or global. Linear or affine gaps.

Smith–Waterman and Needleman–Wunsch with score-only paths, traceback, CIGAR output, and built-in biological matrices.

Explore alignment →

NAMES + RECORDS

Match how it sounds, not only how it is spelled.

PYTHON / UNICODE WITHOUT THE DETOUR

UCS-2 and UCS-4 are first-class SIMD targets.

Python strings do not have to become UTF-8 before alignment. Chinese, Japanese, Korean, Arabic, and emoji use direct UCS-1, UCS-2, or UCS-4 access and stay on the vectorized path.

ONE QUERY × MANY TARGETS

Batch work is the primary path.

Reuse the prepared query profile across candidate lists, or run full all-pairs cdist with thresholds, pruning, and per-query top-k.

03 / DUCKDB

SIDELOADED EXTENSION

SIMD string matching.
Right inside DuckDB.

Load stride-align once, then use its fast pair, vector, ranking, and cdist functions anywhere you write SQL. Pass ordinary DuckDB VARCHAR values—including CJK, accents, and emoji—and get useful results back.

01

FAMILIAR SQL

FAST BY DEFAULT

Rank candidates without sorting every pair.

THE SCORERS YOU EXPECT Pair, vector, cdist, top-k, phonetic, DTW, and matrix APIs.

Use the native stride-align capabilities from SQL, including custom substitution matrices and local/global alignment paths.

PACKAGE DISPATCH Choose the ISA when you choose the package.

Generic, AVX2, AVX-512 BW/VL, NEON, and CPU-tuned Loongson LSX/LASX artifacts keep deployment explicit and make ISA benchmarking reproducible.

NATIVE SURFACE ONLY SQL gets stride-align, not somebody else’s API.

RapidFuzz, Parasail, Jellyfish, and TheFuzz compatibility layers are Python migration aids. DuckDB exposes native stride_* functions only.

04 / PYTHON MIGRATION

One import away means one import away.

Keep familiar Python APIs while moving the work onto stride-align’s kernels. Native Python code should use stride_align directly; existing Python code can take the short road.

See compatibility details →

PYTHON / IN-PROCESS API RUNTIME DISPATCH
$ pip install stride-align 
import stride_align as sa

query = "你好世界"
targets = ["你好世间", "再见世界"]

score = sa.levenshtein_normalized_score(
    query, targets[0]
)
scores = sa.levenshtein_normalized_scores(
    query, targets
)

print(score)  # 0.75

Python wheels inspect the CPU at module load and dispatch calls to the best available backend.

Install the portable source package from the hosted stride-align R repository. A prebuilt arm64 binary is also available specifically for Homebrew R 4.6 on macOS 26 or newer. The package provides pair, batch, selection, and cdist APIs over ordinary R objects, then selects the best compatible packaged backend when its namespace loads. Browse R packages.

DUCKDB / VECTOR SQL PACKAGE DISPATCH
$ pip install duckdb==1.5.5 
import duckdb

db = duckdb.connect(config={
    "allow_unsigned_extensions": "true"
})
extension = "/path/to/stride_align.0.6.0.duckdb_extension"
db.execute(f"LOAD '{extension}'")

match = db.execute(
    """WITH candidates(candidate) AS (
           VALUES ('你好世间'), ('再见世界')
       )
       SELECT candidate,
              stride_levenshtein_similarity(?, candidate) AS score
       FROM candidates
       ORDER BY score DESC
       LIMIT 1""",
    ["你好世界"],
).fetchone()

print(match)  # ('你好世间', 0.75)

Download stride-align 0.6.0 for DuckDB, matching your DuckDB version, platform, and SIMD package. Candidate rows flow through DuckDB's vectorized executor; Python only orchestrates the sideload and query. See the vectorized Bible lookup and spell checker.
